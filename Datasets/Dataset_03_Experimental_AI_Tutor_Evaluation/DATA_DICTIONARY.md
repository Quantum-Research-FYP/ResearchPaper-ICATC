# Data Dictionary — Dataset 03: Experimental AI Tutor Evaluation

## Overview
This dictionary details the data structure and variables of the **85-question experimental evaluation** comparing the **Circuit-Grounded Quantum Tutor** against a **Generic LLM Baseline (GPT-4o)**.

---

## 1. Question Identification & Categorization
* **`question_id`**: Unique identifier for the benchmark item (`Q001` to `Q085`).
* **`category`**: Core quantum computing educational domain:
  * `Circuit understanding` (20 items): Gate operations, statevectors, superposition, and entanglement.
  * `Transpilation` (20 items): Basis gate decomposition, mapping to physical coupling graphs, routing SWAPs.
  * `Hardware execution` (15 items): Coupling maps, native hardware bases, readout errors, and decoherence.
  * `Debugging` (15 items): Diagnosing unintended state collapse, unwanted SWAPs, and phase flip bugs.
  * `Optimization` (15 items): Gate cancellation, commutation rules, and depth reduction passes.
* **`question_title`**: Short descriptive title of the technical concept evaluated.
* **`question_text`**: Standardized prompt text delivered identically to both systems.
* **`circuit_or_compilation_context`**: Complete context supplied alongside the query (OPENQASM 3.0 code, transpilation pass trace, or device coupling topology).
* **`expected_answer_reference_facts`**: Ground-truth technical facts used by expert evaluators to score responses.

---

## 2. Experimental Model Responses
* **`generic_ai_response`**: Response generated by ungrounded baseline model (`GPT-4o`) given the question and context text without internal compiler integration.
* **`circuit_grounded_tutor_response`**: Response generated by the Quantum Circuit Learning Platform Tutor with live AST inspection, transpilation DAG access, and simulation state grounding.
* **`baseline_model`**: Model identifier for baseline (`GPT-4o (Standard Prompting)`).
* **`grounded_tutor_model`**: Model identifier for tutor (`Quantum Circuit Tutor (AST & Trace Grounded)`).

---

## 3. Rubric Evaluation Scores (0–2 Scale per Criterion)
Scored independently by two qualified quantum computing evaluators (`EVAL_01` and `EVAL_02`):
* **`generic_evaluator1_{correctness, relevance, circuit_grounding, explanation_quality}`**: Evaluator 1 scores for Generic AI baseline.
* **`generic_evaluator2_{correctness, relevance, circuit_grounding, explanation_quality}`**: Evaluator 2 scores for Generic AI baseline.
* **`grounded_evaluator1_{correctness, relevance, circuit_grounding, explanation_quality}`**: Evaluator 1 scores for Circuit-Grounded Tutor.
* **`grounded_evaluator2_{correctness, relevance, circuit_grounding, explanation_quality}`**: Evaluator 2 scores for Circuit-Grounded Tutor.
* **`*_total_0_8`**: Composite score sum across all four criteria (range: $0$ to $8$).

---

## 4. Hallucination Evaluation Fields
* **`generic_hallucination_flag_evaluator1`**: Binary flag ($1 = \text{Hallucination detected}$, $0 = \text{No hallucination}$) by Evaluator 1.
* **`generic_hallucination_flag_evaluator2`**: Binary flag by Evaluator 2.
* **`grounded_hallucination_flag_evaluator1`**: Binary flag for Grounded Tutor by Evaluator 1.
* **`grounded_hallucination_flag_evaluator2`**: Binary flag for Grounded Tutor by Evaluator 2.
* **`generic_hallucination_class`**: Adjudicated classification (`No Hallucination` vs `Unsupported routing/cause claim`).
* **`grounded_hallucination_class`**: Adjudicated classification (`No Hallucination`).

---

## 5. Experimental Protocol & Integrity Controls
* **`response_order_for_blinded_review`**: Blinded presentation order (`A=Generic, B=Grounded` vs `A=Grounded, B=Generic`) presented to evaluators.
* **`final_evaluation_status`**: Experimental completion flag (`EMPIRICAL_EVALUATION_COMPLETED`).
* **`evaluator1_id`**: Anonymized ID of first expert evaluator (`EVAL_01`).
* **`evaluator2_id`**: Anonymized ID of second expert evaluator (`EVAL_02`).
